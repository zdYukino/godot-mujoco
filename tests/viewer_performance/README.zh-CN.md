# Godot / MuJoCo 原生 viewer 性能对照

在真实 Linux GPU 会话运行，默认使用仓库固定的 Godot 4.7.2 / MuJoCo 3.16.0。

```bash
python3 tests/viewer_performance/run.py --out ../godot-mujoco-benchmarks/viewer-performance
```

正式采样包括几何画廊、单/双 G1，共同基础画面和默认画面；每个图形项目预热 10 秒、采样 30 秒、重复三次。两端交错执行，第二轮反转顺序。`--quick` 缩短为预热 1 秒、采样 3 秒、一次，仅验证工具，不产生验收通过结论。`--resume` 复用同一输出目录的冻结源码、构建和已完成结果；不得把短测目录当正式测试继续。

`static` 冻结场景运行回调，用于纯绘制对照；`running` 保留完整运行路径。另增加一次 `paused` 诊断，保留暂停时仍在执行的节点回调，以区分绘制成本与无效状态同步。默认画面只测运行状态。实际绘制区域固定为 1920×1080，使用 X11 全屏会话；窗口尺寸不符时拒绝比较。

共同画面关闭 Godot 自动鼠标拾取，与原生 viewer 没有点击时的行为一致。默认画面保留原设置并将鼠标固定在视口中心，单独记录射线查询耗时；不能把这部分 CPU 开销解释为 GPU 渲染开销。

窗口系统可能没有持续向窗口派发悬停事件，开关开启时也可能只有少量帧产生查询。报告逐轮列出实际射线次数、有查询帧占比、最大停顿和射线累计时间占采样墙钟的比例；不能将射线 p95 为零解读为没有查询。默认画面汇总不作为验收结论。

运行前需要 `cmake`、C++ 编译器、X11/OpenGL 开发库、`glxinfo`，以及已经准备好的 `build-linux/_deps/mujoco-src` 和 `godot-cpp-src`。路径可以用 `--godot`、`--mujoco-root`、`--godot-cpp` 指定。构建和测量都在 `--out` 内进行，正常插件构建默认不包含测试入口。

工作区有并行修改时，可以用 `--snapshot <先前输出目录>` 从已经验证的冻结运行时代码开始新一轮测试，并使用当前测试工具。报告保留父快照、源文件哈希、初始工作区差异和二进制哈希，避免混用版本。

输出：

- `report.md`、`results.json`：分场景对照、有效性和门槛结果。
- `environment.json`、`source-files.json`、`source.patch`：硬件、版本、构建及待测源码。
- `fixtures/`：活动组合世界的 MJB、`mjSTATE_INTEGRATION` 小端 f64 状态、视角、可见 geom ID 和编译任务来源。
- `runs/`：每帧 CSV、运行元数据、截图、日志、最后状态和 RSS/温度环境记录。
- `audit.json`：原始 CSV、二进制与脚本指纹、截图尺寸、相机投影和 time/qpos/qvel/act 轨迹复核。
- `fixture-adjustments.json`：仅在隔离副本中校正的旧版资源依赖键；原先引用的资源路径与实际 SHA-256 必须吻合，资源字节不变。

正式门槛仅用于共同基础画面：每个场景的 p95 帧时不超过原生 1.2 倍，独立物理吞吐不少于原生 90%。软件渲染、疑似呈现限速、状态不一致、缺少场景/轮次，都不能得到整套通过结论。GPU timer 不可用时明确留空。

不同进程的运行时 RID 前缀会变化。测试入口先比较全部非名称模型数组、物理选项和可视化设置，再在专用测试世界中载入同一份 MJB 并重绑名称；载入后的 MJB 哈希必须与夹具相同。正式插件不提供这一入口。续跑时，模型、状态、相机、可见集合、测试脚本或二进制指纹变化都会使旧结果失效。

夹具必须实际包含单 G1 的 36/35 或双 G1 的 72/70 个位置/速度自由度，防止模型未注册时只测到地面。建议将正式结果保存在持久目录。可以独立复核已有数据，不启动图形窗口：

```bash
python3 tests/viewer_performance/run.py --audit-only --out ../godot-mujoco-benchmarks/viewer-performance
```

原生基线使用官方 `mjv_updateScene` / `mjr_render`，相当于无 UI 的独立最小 viewer，不是包含面板、后台物理线程和历史记录的完整 `simulate`。Godot 保留现有场景节点、脚本、状态同步和隐藏碰撞更新路径。两端隐藏 UI 绘制；共同画面禁用效果并用无光照材质；默认外观不等价，单独报告。这个比较用于定位集成开销，不能直接推导原生画面嵌入 Godot 的成绩。

报告逻辑的校验：

```bash
python3 -m unittest discover -s tests/viewer_performance -p 'test_*.py'
```

后续需求已锁定：标准运行场景默认启用 MuJoCo 3.16.0 原生手势与按键；完整原生面板用 Godot 控件实现并尽量复刻外观；保持当前模型能力边界并解释置灰项；原生重置与快照恢复分开；运行调整临时生效、导出另存。渲染架构在性能报告后决定。
