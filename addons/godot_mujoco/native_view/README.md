# Experimental shared-world native view

This runtime-only Linux x86_64/X11/OpenGL integration is disabled by default. It is an isolated prototype, not a production or performance acceptance. The candidate custom Godot 4.7.2 engine is the host used in development tests; direct-to-screen additionally depends on its rendering patches. R17 has not passed independent review or production acceptance. See `docs/development/native-view-r17/README.md`.

Build the plugin with `-DGMJ_NATIVE_VIEW_EXPERIMENTAL=ON`. This adds the read-only backend snapshot method and generates `native_view/bin/bridge.gdextension`. An OFF configure removes that generated registration. The source `.gdextension.in` does not auto-load. OpenGL and X11 development libraries are required for the experimental build.

On `MjRuntimeWorld`, opt in with `native_view_experimental = true`. Leave `native_view_direct_experimental = false` for ordinary GPU texture composition; set it true only with the reviewed custom engine and the single-window contract. `start_native_view()` and `stop_native_view()` support explicit runtime control. Changing the exported flag alone after startup does not toggle a running view. A flag enabled before tree entry arms one start after the first committed `world_ready`; an explicit stop cancels that pending start. Early manual start remains in a waiting state across initial compilation and failed candidates until a valid design is committed. A closed or invalid world is terminal, and explicit restart is rejected.

The original shared world remains the only simulation authority. A bounded model snapshot is copied on committed revision changes, with an integration-state snapshot each accepted frame. The render thread owns a disposable display model/data pair, calls `mj_forward` to reconstruct display data, and never steps physics. No shared-world raw pointers cross the render queue. G1 measurements apply only to the isolated controlled comparison documented with the revision 12/13 evidence; they do not establish production performance. The inherited `step_ms` diagnostic field currently measures display-state restore/forward work, not physical stepping.

Only after a valid native texture arrives does the controller hide Godot 3D, suspend model transform reads/sync, and disable automatic picking. Godot 2D controls remain interactive above the background. Left drag orbits; wheel zooms. Existing control and step commands still operate on the shared physics world. Stable rid/prefix identities accompany model revisions, but native selection, tracking and perturbation are not implemented.

On stop or a recoverable error, canvas references are removed, RenderingServer is synchronized, GPU resources are released, and the prior camera/visibility/picking states are restored. Model transforms are refreshed before showing the Godot fallback. Any custom manual draw/capture after worker submissions must call `RenderingServer.force_sync()` before requesting direct drawing and `force_draw()`; worker join alone is insufficient.

The raw bridge mutation methods must be called from the main thread. Submit canvas replacement/clear commands before `acknowledge(generation)`; acknowledgement itself is queued on RenderingServer, so earlier draws retain the old texture. Use only a generation actually published by this bridge, never reuse a retired texture after acknowledging its replacement, and never free the bridge before `finish()` drains its queue. Worker calls to configuration, request, acknowledgement and stop are rejected/ignored; `snapshot()` is the mutex-protected read interface. These restrictions also apply in Separate mode.

Editor/game test communication uses a unique run ID under `user://mj-live-tests/`, atomic numbered command files and explicit accepted/completed results. Readers reject another run's state. The test harness quarantines legacy fixed-name files in its isolated test project, and logs actual Continue request IDs/results; a write to disk alone is not a passed command.

Current boundaries:

- One main runtime window and the same viewport as the owning MjRuntimeWorld; physics must remain on the main thread. Safe and Separate rendering threads were tested.
- Do not create a second native window in Separate mode: even the official Godot 4.7.2 engine without plugins emits GLX errors. Safe mode can fall back, but multiple windows are not part of the supported configuration.
- No mixed Godot 3D/native depth composition, custom Godot shaders/particles, exact contact-force diagnostics, MuJoCo plugins, or worlds above 9000 geoms. Model payload limit remains 64 MiB by default. The isolated candidate accepts explicit `rendering/mujoco_native_view/max_model_mib` in 1..192; values outside that range fail closed. This is not a production recommendation. Profile-only calls use `scene_native_view_snapshot(space, known_revision, false)` and do not allocate model bytes. The model/data/scene CPU admission estimate is capped at 256 MiB; rigid geometry is limited to 600k mesh vertices, 1M mesh faces and 64 MiB texture data. Skins and flexes are excluded. State transport is capped at 8 MiB.

The runtime acquires one process-wide native-view lease before requesting model bytes and checks mailbox readiness before snapshotting. The mailbox holds one request. Packed model arrays use Godot COW storage; the display loads directly with MuJoCo 3.16 `mj_loadModelBuffer`, without a VFS staging copy. A replacement releases the previous display model/data/GPU context before decoding the next one; decode/data failure stops the view and restores Godot. The old shared color texture can remain visible until the queued switch completes. CPU admission accounts for one resident display (<=256 MiB), one serialized model (<=192 MiB), and up to three bounded state buffers (<=24 MiB), below 512 MiB. This is owned-buffer accounting, NOT a hard process-RSS or GPU-driver-memory guarantee; compiler, authoritative world, Godot meshes, allocator caching and driver allocations remain additional. Do not share or retain model packets in application caches.

Low-level bridge users must acquire `acquire_transport()` before their first request and call `ready_for_request()` before generating a packet; always `finish()` before destroying the bridge. `configure_comparison` is a frozen, pre-submission diagnostic camera/visible-name interface with flat materials; it is not an interactive camera or production appearance path. `GMJ_NATIVE_MEMORY_TRACE=1` enables load-boundary RSS/HWM observations and should remain off during timing.
- Screen-dependent canvas features may force engine offscreen composition. Some guards remain process-lifetime disable flags; the controller does not repeatedly override them.
- MuJoCo SeparationRay remains unsupported for collision. The engine guard only prevents invalid RID updates; it does not supply collision semantics.
- Ray picking on a valid closed authoring world returns empty without attempting reconstruction. Invalid handles, non-finite ray inputs, and actual reconstruction failures retain their diagnostics. This does not extend support to other query kinds.
- The inherited bridge still fail-stops the runtime process if GL context restoration becomes irrecoverable. Rendering is rejected in editor-hint mode and the public controller rejects unsupported platforms, but this is not an editor/device-loss recovery solution. The raw bridge methods are internal experimental test interfaces, not a general rendering API.

See the integration report and source/test manifests before reusing the patch. No performance target or production readiness is claimed.

Revision 13 admission uses checked nonnegative arithmetic for every resident component, profile product and cumulative size. After decoding, the bridge independently sums the pinned MuJoCo 3.16 `MJDATA_POINTERS` fields with conservative per-field alignment before calling `mj_makeData`; packet metadata alone cannot authorize the allocation. Actual allocated data size is checked again. A candidate model/data pair has RAII ownership through rejection, and Godot packed-array resize failures return an error. This is not a sandbox for arbitrary hostile MJB files or a guarantee of recovery from MuJoCo fatal errors, process OOM, or driver failure.

Diagnostic environment variables (off by default, exclude from performance samples):
- `GMJ_DIAGNOSTIC_STATE=1` compares every integration-state component after restore and after forward. Counters report actual comparisons and changing input components. Passive G1 has no actuators, so this does not validate changing control input.
- Linker `--wrap=mj_step/mj_step1/mj_step2` counts bridge-origin step calls. It does not intercept calls originating inside other DSOs. The old constant `physics_steps` field is removed; `bridge_step_calls` is measured. `GMJ_DIAGNOSTIC_STEP_CONTROL=1` with state diagnostics deliberately steps the first disposable display frame once as a positive control and must never be used for normal display or timing.
- `GMJ_DIAGNOSTIC_MEMORY=1` enables the main-thread `diagnostic_allocator(trim)` test hook, returning glibc `mallinfo2` observations and optionally calling `malloc_trim(0)`. It is not an automatic production memory remedy. Trim demonstrates reclaimable free pages only; remaining allocation growth requires attribution.

The pinned godot-cpp generated `Dictionary::operator=(Dictionary&&)` does not destroy the old dictionary. Revision 13 uses `replace_dictionary(target, const Dictionary&)` at the bridge's pending/render packet replacement and cleanup sites, and at shared-world committed-definition replacement. This forces the existing destructor-aware copy assignment without editing the user's SDK. The helper is safe for self-assignment. Minimal reproduction and fixed-frame/rebuild comparisons are in the revision 13 evidence. This is a scoped workaround, not an audit or repair of every SDK-generated class or unrelated plugin call site.
