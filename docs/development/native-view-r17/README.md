# Experimental native view: R17 candidate

This branch packages the isolated Godot + MuJoCo native-view experiment for user evaluation. It has **not passed independent R17 review or production acceptance**. An independent review attempt was blocked by the system's safety check; no reason was supplied. The development-side tests must not be described as independent approval. Keep the native view disabled by default.

The plugin patch was prepared from repository commit `39a4c595f4cea78e7d1935f38fc68d5a62b1ecc2`. It includes source and test scripts only, not regenerated `.uid`, extension registration, shared libraries, build outputs, captured models, or logs. The plugin CMake flag `GMJ_NATIVE_VIEW_EXPERIMENTAL` defaults to `OFF`; the runtime `enabled` and `native_view_experimental` flags remain off. See `addons/godot_mujoco/native_view/README.md` for the opt-in interface and platform limits.

## Custom Godot dependency

The tested editor is a custom build, not an official Godot binary. `godot-ed1daf0-to-r17.patch` is the complete cumulative source difference against Godot commit `ed1daf0bf001b61586d9930840f2f1394092c079`. The source archive used for preparation had SHA-256 `e607e9985e1c201bc9cdc1aec8a120f0c3f53b9603f1f828e2b748534a2471ef`. The patch includes experimental direct presentation, editor/debugger and safety changes, image upload snapshots, R17 mutable-parameter snapshots, and diagnostic symbol-build settings. It targets a Godot source tree; do not apply it to this plugin repository.

`engine-manifest.json` lists hashes for all 15 changed files. On an isolated extraction of the pinned archive, `patch -p1 --batch --dry-run -i <absolute-path-to-patch>` can check applicability; applying the patch in that isolated tree should yield the candidate hashes in the manifest. The cumulative patch must not be combined with its component R10/R15/R16/R17 patches. The exact source-patch replay was verified in isolation; a fresh clean build from this branch has not yet been completed.

The development editor was built on Linux x86_64 with X11, OpenGL and Vulkan enabled, .NET SDK 8.0.426, SCons 4.11.1, and options `platform=linuxbsd target=editor arch=x86_64 production=yes optimize=speed lto=none debug_symbols=no module_mono_enabled=yes opengl3=yes vulkan=yes x11=yes wayland=no -j2`. Mono glue and managed assemblies must also be generated against the built editor. Building the experimental plugin needs MuJoCo 3.16.0, godot-cpp `godot-4.5-stable` at `e83fd0904c13356ed1d4c3d09f8bb9132bdc6b77`, X11 and OpenGL development libraries. Configure an isolated plugin checkout with `-DGMJ_NATIVE_VIEW_EXPERIMENTAL=ON` only for testing; `OFF` is the default and removes the generated bridge registration from that checkout. Build dependencies and NuGet caches should be isolated too. These are recorded development parameters, not a verified, bit-reproducible clean-build recipe.

## Evidence and remaining limitations

Development tests on the final R17 engine included 220/220 plugin checks, deterministic drawable/compositor and shader-parameter tests, and a controlled G1 lifecycle test. R16 independently passed a 600-round test, which was **not rerun on the R17 final engine**. These results are bounded development evidence and do not establish the requested full-frame performance goal. The R17 engine binary used then had SHA-256 `7dd5886b15e1699b81a19165caf80f5ba0282b88ae8af71a233310fca0510bba`.

The historical first-switch 2.69 MiB live allocation increase remains unattributed. The backend still retains completed asynchronous threads until shutdown; the reaper is a separate feasibility prototype. The .NET SIGTERM path can exit while the Godot main loop is active and generate cleanup errors; the cooperative-stop test is not integrated into the product. The queue-budget prototype is per-instance and does not provide a global CPU/GPU memory limit. Device loss, OOM, broader platform support, native selection/tracking/perturbation, mixed 3D depth and production performance remain unverified. RID snapshotting does not extend the lifetime of the referenced resources.
